## Defect

### D1: series adoption reports a later occurrence's rule error instead of the first failing occurrence's conflict (S3-039, A-30)

- **Spec.** "The first failing occurrence in index order determines the ordinary booking error."
  A-30 applies "occurrences 1..count−1 in index order, each with the A-02/A-20 order". Occupancy is last *within
  each occurrence*.
- **Setup.**
  - `r_pol` (Europe/Berlin) has a policy effective 2026-12-03 with Thursday hours 18:00-22:00 and a 60-min
    duration (v2). Its policy for 2026-11-19 has hours 18:00-23:00 and a 90-min duration (v3).
  - Ada books p_1 on 2026-11-12 at 21:30, party 2.
  - Bob books p_1 on 2026-11-26 at 21:30.
- **Action.** Ada sends `POST /series {"anchor_reference": <Ada's>, "count": 4, "interval_weeks": 1}`.
  - occurrence 1, 2026-11-19 21:30: OK;
  - occurrence 2, 2026-11-26 21:30: conflicts with Bob's booking → 409 `table_unavailable`;
  - occurrence 3, 2026-12-03 21:30: ends 22:30, after the 22:00 close → 422 `outside_opening_hours`.
- **Expected.** 409 `table_unavailable` (occurrence 2 fails first).
- **Actual.** 422 `outside_opening_hours`.
- **State.** Nothing persists after the failure; Gate checked this. The defect is only in which error is reported.
- **Cause.** `series.adopt` (series.py lines 44-49) calls `place()` for every occurrence first and only then calls
  `ensure_free()` once over all of them. Any rule error in any later occurrence therefore beats an occupancy error
  in an earlier one.
- **Fix direction (Builder's choice).** Check occupancy per occurrence in index order. For each i, `place(i)` then
  `ensure_free` over the occurrences planned so far, before moving to i+1. Mutate only after all pass, as now.
- **Detected independently by:**
  - Gate `probe_s3.py` (FAILED S3-039);
  - Verifier draft suite 73910bf `test_43_series.py::test_first_failing_occurrence_in_index_order_decides`, which
    got the same 422.
