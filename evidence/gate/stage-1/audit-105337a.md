## Defects (ordered by severity)

### D1: 5xx on a valid body with a deeply nested ignored field (S1-006, S1-011; spec §5, §3.4)

- **Spec.** §5: "Requests must not produce 5xx responses, including under concurrent load." §3.4: "Unknown fields
  in a request body are ignored, never an error."
- **Minimal reproducer.**
  1. Reset with any fixture and log in.
  2. Send `POST /reservations` with `Authorization: Bearer <tok>`, `Idempotency-Key: d1000` and this body:
     `{"restaurant_id":"r","table_id":"t","starts_at_local":"2026-10-15T18:00","party_size":2,"x":` +
     `"["*1000 + "]"*1000` + `}`.
- **Expected.** Not 5xx. The field is ignored and the request is processed normally, or the request is rejected with
  400 `malformed_request`.
- **Actual.** `500 {"error":{"code":"internal_error",...}}`. `POST /reservation-moves` behaves the same.

| Nesting depth | Result |
|---|---|
| 500 | 201 |
| 980 | 409 (processed normally) |
| 1000, 1100, 1300, 1600 | **500** |
| 3000, 100000 | 400 |

PATCH, signup and import are not affected. Logs: `logs-105337a/edge-clean-105337a.log` and
`logs-105337a/server-18385-recursionerror.txt`.

- **Cause** (code reading plus the server traceback). `api.Api._idempotent` calls `jsonio.fingerprint(body)`.
  `jsonio._normalise` recurses in Python and raises `RecursionError` above the interpreter's limit of 1000. The C
  JSON decoder accepts these bodies because its own nesting limit is higher. `server._dispatch` then maps the
  exception to 500.
- **State.** No state changes. The failure happens before `action()`, so no receipt is stored.
- **Severity.** Lowest class of defect (pathological input), but it violates an explicit "must not" with no
  exception. Under the Gate mandate, an error-case gap blocks acceptance.

### Observation, not blocking: pre-1893 offsets

Europe/Berlin dates before 1893 render the LMT offset with seconds, for example
`1890-01-02T18:00:00+00:53:28`. RFC 3339 offsets are HH:MM only (§3.4). The spec's "any calendar date" (§4)
combined with true IANA offsets (§9) cannot be satisfied in RFC 3339 here, so Gate does not block on this.

## Code audit (stage-1 source at 105337a)

- **Serialisation.** `store.Store.lock` is one `threading.Lock`. Every handler that reads or writes state holds it
  for the whole read-validate-write (`api.py`, lines 159-227). Only scrypt runs outside it. Signup re-checks email
  uniqueness under the lock after hashing (`api.py` 128-137). Login re-checks `self.store.state is state` so that a
  reset or import in between cannot hand out a token for a replaced state (`api.py` 150-154). Conclusion:
  concurrent writers cannot interleave.
- **Idempotency.** `Api._idempotent` (`api.py` 55-78) keys receipts on (user id, method, path, key). It resolves
  them after auth and the JSON-object parse and before any field validation, and checks and stores the receipt
  in the same locked step as the write. Only 2xx is stored (a raised ApiError skips the store). A replay returns the
  stored dict, which is a fresh `to_response()` dict that is never mutated afterwards. Conclusion: retries replay
  and do not repeat.
- **Occupancy.** `booking.ensure_free` (`booking.py` 101-117) is the single check, over half-open UTC intervals
  (`model.Reservation.overlaps`). Create, PATCH and moves call it before any mutation.
- **All-or-nothing moves.** `booking.move` (`booking.py` 272-294) plans every item with `plan_amendment` (no
  mutation), runs `ensure_free` once over all placements (no-op items stay in `fixed`), then applies. Error order
  matches A-12.
- **PATCH and cancel.** Validate fully before mutating. Cutoff is `start - now <= cutoff` (A-03). Cancel is
  idempotent.
- **DST.** `timeutil.exists` round-trips the local time to detect gap times. `to_instant` uses `fold=0` (first
  occurrence). Durations are added to UTC instants, so they are absolute. The slot grid is wall-clock from `opens`.
  All per §9 and A-08.
- **Reset and import.** Both build and validate a complete new `State` outside the lock, then swap it in under the
  lock, so a rejected import changes nothing. Export copies under the lock with `deepcopy`. Tokens are SHA-256
  digests and passwords are `scrypt$...`, so no plaintext credentials appear in the export (checked by the probe).
- **Special-casing.** No IDs, dates, references or other check inputs are hard-coded in the product.
- **Weakness found.** D1, the recursive `_normalise` reached from every idempotent write.
