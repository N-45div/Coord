## 5. Code audit (0720c48 stage-3)

- **Policy selection.** `policies.select` takes the greatest `effective_from` ≤ local start date, ties by greatest
  version, otherwise policy 0. `booking.place` validates under it, and the `Placement` carries the policy whose
  `terms()` the booking accepts. Publication validation is `parse_publication`: every defect is 422 (A-28),
  capacities must name exactly the tables, and opening hours have unique weekdays. The endpoint order (auth → body
  → idempotency → 404 → 403 → 422) matches A-27.
- **Revision and history writes in one place.**
  - `Reservation.record` appends `seq = len+1` with the resulting revision and a deep copy of the terms.
  - Callers:
    - `new_reservation` (created);
    - `apply_change` (changed: replaces fields, terms and end, revision +1; used by PATCH and moves);
    - `cancel` (cancelled, revision +1, only when not already cancelled).
  - A no-op returns from `plan_amendment` before any write.
  - `plan_amendment` order is expected_revision → cancelled → accepted cutoff (`res.cutoff_minutes` from the
    accepted terms) → fields → rules under the resulting date's policy (A-29).
- **Counters.**
  - `touch_series` bumps each affected series once per operation (set of series ids).
  - The diner exception is set in `apply_change`; cancel does not set it.
  - `bump_restaurant` runs on create, real PATCH, cancel, publication, a batch with any change, and adoption
    (A-32, not exposed in stage 3).
- **Series atomicity.** `series.adopt` validates the anchor (A-30 order), plans each occurrence with `place`, then
  `ensure_free` in index order. It creates nothing until all pass. The idempotency layer stores 2xx only.
- **Imports.** `model.state_from_json` accepts stage 1, 2 and 3 state. `_with_original_history(seeded=False)`
  gives revision 1, policy-0 terms and a created entry, plus cancelled at revision 2 (A-31). Seeds use
  `seeded=True` (A-43, cancelled at revision 1). Receipts keep their original bodies.
- **Concurrency.** Unchanged single store lock: read-validate-write per request.
- **Stage-4 surface (A-17):** none. No closures or replans; restaurant revision is not exposed; the harness stage-4
  probe fails.
